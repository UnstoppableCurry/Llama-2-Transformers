脚本实际怎么用多 GPU

hg8gpu.py 大约 50 行，是一份薄脚本：导入、初始化进程组、加载模型、包一层 DDP、然后进入对话循环。它没有单独的服务进程、配置文件或分层模块。

不要把它读成已验证的 8 卡生产服务。 文件名和 num_gpus = 8 只说明脚本按 8 张卡来写。仓库没有吞吐、显存或在线服务实现，本页只转述源码调用。

先说结论

脚本没有使用 Hugging Face / Accelerate 常见的 device_map（例如 device_map="auto"）把层分到多张卡。它做的是：

  1. 把整模 .to(device_ids[0])，先放到 GPU 0；
  2. 再包 torch.nn.parallel.DistributedDataParallel；
  3. 进程组用 NCCL，world_size=8，但 rank 写死为 0。

注释写「将模型拆分到多个GPU上」，但所用 API 是 DDP。DDP 的常规语义是数据并行（各进程一份模型副本），不是按层切分的模型并行。

按执行顺序

设备数量 num_gpus = 8，torch.cuda.set_device(0)。当前进程绑到 cuda:0。
进程组 dist.init_process_group(backend='nccl', init_method='tcp://localhost:23456', world_size=num_gpus, rank=0)，然后 dist.barrier()。
加载 from_pretrained("meta-llama/Llama-2-70b-chat-hf")，整模 .to(device_ids[0])。
并行包装 DistributedDataParallel(model, device_ids=list(range(8)))，再 model.half()。
推理循环 input("You: ") → tokenizer.encode → 放到 GPU 0 → inputs.half() → 可选拼接 context → model.generate(..., max_length=200)。
退出 输入 exit 后打印 Goodbye，再 dist.destroy_process_group()。

和常见多 GPU 推理写法的对照

源码做法对照
做法 本仓库 hg8gpu.py
Hugging Face device_map / Accelerate 分层放置 未出现
流水线并行或张量并行框架 未出现
torch.nn.parallel.DistributedDataParallel 有，device_ids 为 0–7
整模先放到单卡 有，.to(device_ids[0])
用 torchrun 或 spawn 拉起多个 rank 未见；rank=0 写死，单文件直接 python hg8gpu.py
HTTP 服务、批处理、健康检查 未见

源码摘录

设备与并行相关的语句如下（与仓库文件一致）：

num_gpus = 8
torch.cuda.set_device(0)

dist.init_process_group(
    backend='nccl',
    init_method='tcp://localhost:23456',
    world_size=num_gpus,
    rank=0,
)
device_ids = list(range(num_gpus))
dist.barrier()

tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-70b-chat-hf")
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-70b-chat-hf"
).to(device_ids[0])

model = torch.nn.parallel.DistributedDataParallel(model, device_ids=device_ids)
model = model.half()

README 用 git clone 拉取的是 NousResearch/Llama-2-70b-chat-hf；脚本 from_pretrained 写的是 meta-llama/Llama-2-70b-chat-hf。仓库没有把本地克隆目录接到加载路径上。这是文件之间的差异，不是额外结论。

对话循环里还做了什么

  • 用户输入经 tokenizer.encode(..., return_tensors="pt") 后放到 GPU 0，再 .half()。
  • 若已有 context，在最后一维与当前输入拼接。
  • torch.no_grad() 下调用 generate，pad_token_id=tokenizer.eos_token_id。
  • 解码 outputs[0, inputs.shape[-1]:]，打印 Model: 前缀。
  • 把 outputs[:, inputs.shape[-1]:] 存进 context，供下一轮使用。
